# Pharos NFT Creator — Інструкція користувача

## Огляд

Навичка (Skill) для Pharos Agent Center, яка дозволяє AI-агентам створювати повноцінні NFT-колекції повного життєвого циклу на блокчейні Pharos. Підтримує генеративний (на основі ознак), індивідуальний та одиночний режими створення зображень. Ви спілкуєтеся з агентом природною мовою, а він бере на себе генерацію зображень, завантаження на IPFS, розгортання смарт-контрактів, мінтинг та розподіл.

## Можливості

- Автоматична перевірка залежностей при кожному виклику (Python, Forge, Cast, Node.js тощо)
- Автоматичне створення файлу `.env` зі змінними середовища
- Автоматична нормалізація приватного ключа (вставляйте з префіксом `0x` або без)
- Три режими створення зображень: генеративний (ознаки), індивідуальні зображення, одиночне зображення
- Генеративне створення NFT з шарами ознак та вагою рідкісності
- Позаблокчейн-композиція зображень із PNG-шарів за допомогою Python Pillow
- Завантаження папок зображень + метаданих на IPFS через Pinata (SDK для файлів, REST API для папок)
- Патерн BaseURI — контракт повертає `ipfs://CID/tokenId` для кожного NFT
- Вбудовані дані мережі Pharos — обирайте testnet/mainnet, RPC налаштовується автоматично
- Розгортання смарт-контрактів ERC-721 з 6 режимами мінтингу (публічний безкоштовний/платний, лише власник, вайтлист безкоштовний/платний, вайтлист безкоштовний + публічний платний)
- Необов'язкова цільова сторінка мінтингу (HTML + ethers.js, автоматичне налаштування)
- Пакетний мінтинг та airdrop на будь-яку кількість гаманців (вбудовано або з файлу)
- Підтримка вайтлисту через дерево Меркла (автогенерація з коректними proof)
- Аналітика холдерів з експортом у JSON/CSV
- Агент спілкується мовою користувача

## Перший запуск — Автоматичні перевірки

При першому виклику навички агент автоматично запускає **Фазу 0: Перевірку залежностей**:

1. **Перевіряє інструменти** — Python, Pillow, Forge, Cast, jq, Node.js, Pinata SDK. Пропонує встановити відсутні.
2. **Створює файл `.env`** — якщо його немає в проєкті, копіює з `.env.example` з плейсхолдерами.
3. **Перевіряє змінні** — чи заповнені `PRIVATE_KEY`, `PINATA_JWT`.
4. **Направляє до `.env`** — якщо секрети порожні, показує **шлях до файлу** та вказує, які рядки заповнити.

RPC-URL Pharos та дані мережі **вбудовані в навичку** — ручне налаштування не потрібне. Ви просто обираєте мережу під час конфігурації.

Приклад виводу:

## Змінні середовища

Усі секрети зберігаються у файлі `.env` у корені проєкту. **Ніколи не вставляйте ключі безпосередньо в чат.**

Файл `.env` (створюється автоматично):
```bash
# Приватний ключ вашого гаманця.
# Вставляйте з префіксом 0x або без — навичка автоматично нормалізує його.
# БЕЗПЕКА: Заповнюйте файл безпосередньо. НЕ вставляйте в чат.
PRIVATE_KEY=

# Pinata JWT-токен — як його отримати:
#   1. Перейдіть на https://app.pinata.cloud → зареєструйтесь / увійдіть
#   2. Ліва бічна панель → "API Keys" → "New Key"
#   3. Назвіть його (наприклад, "nft-builder"), залиште стандартні дозволи
#   4. Натисніть "Create Key" → скопіюйте JWT (довгий рядок, що починається з "eyJ...")
#   5. Вставте нижче
PINATA_JWT=

# Мережа обирається під час конфігурації — RPC URL налаштовувати вручну не потрібно.
```

### Де отримати значення

| Змінна | Джерело |
|--------|---------|
| `PRIVATE_KEY` | MetaMask → три крапки → Деталі акаунта → Показати приватний ключ. Вставляйте з `0x` або без — автоматично нормалізується |
| `PINATA_JWT` | [app.pinata.cloud](https://app.pinata.cloud) → API Keys → New Key → скопіюйте JWT |

## Підготовка зображень

Навичка підтримує **три режими створення зображень**:

### Режим A: Генеративний (ознаки)

Класичний генеративний підхід — кілька шарів ознак випадково комбінуються. Усі файли мають бути у форматі PNG, RGBA, однакового розміру.

```
traits/
├── Background/
│   ├── blue.png
│   ├── red.png
│   └── green.png
├── Body/
│   ├── normal.png
│   └── muscular.png
├── Headwear/
│   ├── none.png          (порожній прозорий PNG)
│   ├── crown.png
│   ├── cap.png
│   └── helmet.png
└── Weapon/
    ├── none.png
    ├── sword.png
    └── axe.png
```

### Режим B: Індивідуальні зображення

Папка з готовими PNG-файлами — кожен файл = один унікальний NFT. Ви призначаєте вагу рідкісності для кожного. Надайте конфігурацію у форматі JSON/CSV або введіть вручну.

```
my-nfts/
├── 001_samurai.png     (вага: 10 — легендарний)
├── 002_ninja.png       (вага: 30 — незвичайний)
├── 003_wizard.png      (вага: 5 — легендарний)
├── 004_knight.png      (вага: 55 — звичайний)
└── ...
```

Конфігурація (необов'язкова, JSON):
```json
[
  {"file": "001_samurai.png", "weight": 10, "name": "Samurai"},
  {"file": "002_ninja.png", "weight": 30, "name": "Ninja"}
]
```

### Режим C: Одиночне зображення

Один PNG для всіх NFT. Кожен токен виглядає однаково. Підходить для членських квитків, пропусків, утилітарних NFT.

```
collection-art.png    (єдине зображення для всієї колекції)
```

### Вагові коефіцієнти рідкісності (для режимів A та B)

Ваги визначають, наскільки часто зустрічається кожен варіант ознаки. Більша вага = частіше:

| Категорія | Вага | Частота |
|-----------|------|---------|
| Легендарний | 1–4 | Дуже рідкісний |
| Рідкісний | 5–19 | Незвичайний |
| Незвичайний | 20–49 | Помірний |
| Звичайний | 50–100 | Частий |

Приклад: якщо Headwear має Crown(5), Cap(30), Helmet(40), None(25), то Crown з'являтиметься приблизно у 5% згенерованих NFT.

## Використання

### 1. Початок створення колекції

Скажіть агенту:
> "Розгорни генеративну NFT-колекцію на Pharos"

Агент перевірить залежності, створить `.env` за потреби та розпочне інтерактивну конфігурацію.

### 2. Дайте відповіді на питання конфігурації

Агент запитає про:
- **Яку мережу використати** — Pharos Atlantic Testnet (безкоштовно, для тестування) або Pharos Mainnet (реальні токени PROS)
- Назву та символ колекції
- Опис
- Загальну пропозицію (максимальна кількість NFT)
- Тип мінтингу (див. нижче)
- **Режим створення зображень** — генеративний (ознаки), індивідуальні зображення або одиночне зображення
- Деталі зображень: шари ознак, або папка з PNG-файлами + ваги, або шлях до одного PNG

### 3. Типи мінтингу

Агент пояснить кожен варіант і допоможе обрати. Доступні шість типів:

| Тип | Опис | Варіант використання |
|-----|------|---------------------|
| **Public Free** | Будь-хто може мінтити безкоштовно | Відкриті колекції для спільноти |
| **Public Paid** | Будь-хто платить встановлену ціну | Преміальні колекції |
| **Owner-Only** | Мінтити може лише власник контракту | Airdrop-и, приватні розподіли |
| **Whitelist Free** | Лише адреси з вайтлисту можуть мінтити безкоштовно | Ексклюзивні дропи для спільноти |
| **Whitelist Paid** | Лише адреси з вайтлисту платять за мінтинг | Преміальні дропи для спільноти |
| **WL Free + Public Paid** | Вайтлист — безкоштовно, всі інші платять | Нагороди спільноти + публічний продаж |

Для типів з вайтлистом необхідно надати список адрес (файл або вбудовано). Агент автоматично згенерує дерево Меркла та завантажить його в контракт.

### 4. Після розгортання

**Мінтинг та розподіл NFT:**
> "Змінть 50 NFT з моєї колекції та надішліть їх на адреси з файлу airdrop_list.txt"

Формат файлу адрес — одна адреса на рядок:
```
0xAAA...BBB...CCC...
# Рядки, що починаються з #, є коментарями
```

Або вбудовано:
> "Змінть 3 NFT та надішліть на: 0xAAA..., 0xBBB..., 0xCCC..."

**Перегляд холдерів:**
> "Покажи всіх холдерів моєї NFT-колекції"

**Експорт у файл:**
> "Експортуй дані про холдерів у CSV"

**Налаштування вайтлисту:**
> "Налаштуй вайтлист для моєї колекції, використовуючи ці адреси: 0xAAA, 0xBBB"

**Оновлення параметрів мінтингу:**
> "Увімкни публічний мінтинг за 0.05 PROS, макс. 5 на гаманець"

## Усунення несправностей

| Проблема | Рішення |
|----------|---------|
| Невідповідність розмірів PNG | Перевірте, що всі файли мають однаковий розмір, переекспортуйте за потреби |
| Помилка завантаження на IPFS | Перевірте `PINATA_JWT` у `.env` та квоту облікового запису Pinata |
| **Pinata: ліміт 500 файлів** | Безкоштовний тариф = 500 файлів, 1 ГБ. Режим A: ~250 NFT (2N файлів). Режим B: до 500-M NFT. Режим C: до ~500 NFT |
| Forge не знайдено | Встановіть: `curl -L https://foundry.paradigm.xyz \| bash && foundryup` |
| Pillow не знайдено | Встановіть: `pip install Pillow` |
| Помилка **Stack too deep** | Додайте `via_ir = true` до `foundry.toml` — необхідно для цього контракту |
| Помилка компіляції Forge | Переконайтеся, що OpenZeppelin v5 встановлено: `forge install https://github.com/OpenZeppelin/openzeppelin-contracts@v5.0.2 --no-git` |
| Транзакція не проходить на Pharos | Завжди використовуйте прапорець `--legacy` з `forge create` та `cast send` |
| Недостатньо газу | Перевірте баланс гаманця на Pharos |
| Мінтинг не працює | Переконайтеся, що ви є власником контракту, та publicMintEnabled увімкнено для публічних колекцій |
| `.env` не завантажується | Кожна bash-команда має починатися з `set -a && source .env && set +a` |
| Зображення NFT не відображається в експлорері | Переконайтеся, що метадані використовують `ipfs://CID` (не gateway-URL). Перевірте коректність CID папки. |

## Безпека

- **Ніколи не вставляйте** приватні ключі, JWT-токени чи будь-які секрети в чат
- Усі секрети зберігаються **лише у файлі `.env`** — агент читає його автоматично
- `.env` автоматично додається до `.gitignore`
- `state.json` також додається до `.gitignore`
- Переконайтеся, що ви контролюєте ключ власника контракту
| Якщо ви випадково вставили секрет у чат — негайно замініть цей ключ

## Структура вихідних файлів

Після виконання навички ваш проєкт міститиме:

```
project/
├── .env                         # Ваші секрети (НІКОЛИ не комітьте!)
├── .gitignore                   # .env та state.json виключено
└── nft-collection/
    ├── traits/                  # Оригінальні PNG-файли ознак (Режим A)
    ├── composed/                # Зібрані фінальні NFT-зображення (Pillow)
    ├── metadata/                # JSON-метадані для кожного токена (іменовані за ID)
    ├── src/                     # Solidity-контракт (Foundry)
    ├── landing/                 # Веб-сторінка мінтингу (необов'язкова, Фаза 5)
    ├── state.json               # Локальна база даних колекції
    └── holders.json             # Дані про холдерів (після аналітики)
```
