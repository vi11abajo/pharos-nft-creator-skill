# Pharos NFT Creator — उपयोगकर्ता गाइड

## अवलोकन

एक Pharos Agent Center Skill जो AI एजेंट्स को Pharos ब्लॉकचेन पर पूर्ण-जीवनचक्र NFT संग्रह बनाने में सक्षम बनाता है। यह जेनरेटिव (trait-आधारित), व्यक्तिगत छवि और एकल-छवि मोड का समर्थन करता है। आप प्राकृतिक भाषा में एजेंट के साथ बातचीत करते हैं, और यह छवि निर्माण, IPFS अपलोड, स्मार्ट कॉन्ट्रैक्ट परिनियोजन, मिंटिंग और वितरण को संभालता है।

## विशेषताएँ

- हर आह्वान पर स्वचालित निर्भरता जाँच (Python, Forge, Cast, Node.js, आदि)
- पर्यावरण चर के साथ `.env` फ़ाइल का स्वचालित निर्माण
- प्राइवेट की का स्वचालित सामान्यीकरण (`0x` उपसर्ग के साथ या बिना पेस्ट करें)
- तीन आर्टवर्क मोड: जेनरेटिव (traits), व्यक्तिगत छवियाँ, एकल छवि
- Trait परतों और दुर्लभता भार के साथ जेनरेटिव NFT निर्माण
- Python Pillow का उपयोग करके PNG परतों से ऑफ-चेन छवि संयोजन
- Pinata के माध्यम से छवियों + मेटाडेटा फ़ोल्डर का IPFS अपलोड (फ़ाइलों के लिए SDK, फ़ोल्डरों के लिए REST API)
- BaseURI पैटर्न — कॉन्ट्रैक्ट प्रत्येक NFT के लिए `ipfs://CID/tokenId` लौटाता है
- Pharos नेटवर्क डेटा अंतर्निहित — testnet/mainnet चुनें, RPC स्वचालित रूप से कॉन्फ़िगर होता है
- 6 मिंट मोड के साथ ERC-721 स्मार्ट कॉन्ट्रैक्ट परिनियोजन (public free/paid, owner-only, whitelist free/paid, whitelist free + public paid)
- वैकल्पिक मिंटिंग लैंडिंग पेज (HTML + ethers.js, स्वचालित कॉन्फ़िगर्ड)
- किसी भी संख्या में वॉलेट्स में बैच मिंटिंग और एयरड्रॉप (इनलाइन या फ़ाइल से)
- Merkle tree के माध्यम से व्हाइटलिस्ट समर्थन (सही proofs के साथ स्वचालित रूप से उत्पन्न)
- JSON/CSV निर्यात के साथ होल्डर एनालिटिक्स
- एजेंट उपयोगकर्ता की भाषा में संचार करता है

## पहला प्रक्षेपण — स्वचालित जाँच

जब आप पहली बार skill को आमंत्रित करते हैं, तो एजेंट स्वचालित रूप से **Phase 0: Dependency Check** चलाता है:

1. **उपकरणों की जाँच करता है** — Python, Pillow, Forge, Cast, jq, Node.js, Pinata SDK। किसी भी अनुपस्थित को स्थापित करने की पेशकश करता है।
2. **`.env` फ़ाइल बनाता है** — यदि यह प्रोजेक्ट में मौजूद नहीं है, तो प्लेसहोल्डर्स के साथ `.env.example` से कॉपी करता है।
3. **चरों को सत्यापित करता है** — जाँच करता है कि `PRIVATE_KEY`, `PINATA_JWT` भरे हुए हैं या नहीं।
4. **आपको `.env` तक निर्देशित करता है** — यदि रहस्य खाली हैं, तो **फ़ाइल पथ** दिखाता है और बताता है कि कौन सी पंक्तियाँ भरनी हैं।

Pharos RPC URLs और नेटवर्क डेटा **Skill में अंतर्निहित** हैं — किसी मैनुअल कॉन्फ़िगरेशन की आवश्यकता नहीं है। आप बस सेटअप के दौरान नेटवर्क चुनते हैं।

उदाहरण आउटपुट:
```

```

## पर्यावरण चर

सभी रहस्य प्रोजेक्ट रूट में `.env` फ़ाइल में संग्रहीत हैं। **कभी भी कुंजियों को सीधे चैट में पेस्ट न करें।**

`.env` फ़ाइल (स्वचालित रूप से बनाई गई):
```bash
# आपकी वॉलेट प्राइवेट की।
# 0x उपसर्ग के साथ या बिना पेस्ट करें — skill इसे स्वचालित रूप से सामान्यीकृत करती है।
# सुरक्षा: फ़ाइल में सीधे भरें। चैट में पेस्ट न करें।
PRIVATE_KEY=

# Pinata JWT टोकन — इसे कैसे प्राप्त करें:
#   1. https://app.pinata.cloud पर जाएँ → साइन अप / लॉग इन करें
#   2. बाएँ साइडबार → "API Keys" → "New Key"
#   3. नाम दें (जैसे "nft-builder"), डिफ़ॉल्ट अनुमतियाँ छोड़ दें
#   4. "Create Key" पर क्लिक करें → JWT कॉपी करें (लंबी स्ट्रिंग जो "eyJ..." से शुरू होती है)
#   5. नीचे पेस्ट करें
PINATA_JWT=

# नेटवर्क कॉन्फ़िगरेशन के दौरान चुना जाता है — RPC URL मैन्युअल रूप से सेट करने की आवश्यकता नहीं।
```

### मान कहाँ से प्राप्त करें

| चर | स्रोत |
|----------|--------|
| `PRIVATE_KEY` | MetaMask → तीन बिंदु → खाता विवरण → प्राइवेट की दिखाएँ। `0x` के साथ या बिना पेस्ट करें — स्वचालित रूप से सामान्यीकृत होता है |
| `PINATA_JWT` | [app.pinata.cloud](https://app.pinata.cloud) → API Keys → New Key → JWT कॉपी करें |

## आर्टवर्क तैयार करना

Skill **तीन आर्टवर्क मोड** का समर्थन करती है:

### मोड A: जेनरेटिव (Traits)

क्लासिक जेनरेटिव दृष्टिकोण — कई trait परतें यादृच्छिक रूप से संयोजित होती हैं। सभी फ़ाइलें PNG, RGBA, समान आयामों की होनी चाहिए।

```
traits/
├── Background/
│   ├── blue.png
│   ├── red.png
│   └── green.png
├── Body/
│   ├── normal.png
│   └── muscular.png
├── Headwear/
│   ├── none.png          (रिक्त पारदर्शी PNG)
│   ├── crown.png
│   ├── cap.png
│   └── helmet.png
└── Weapon/
    ├── none.png
    ├── sword.png
    └── axe.png
```

### मोड B: व्यक्तिगत छवियाँ

पूर्व-निर्मित PNG का एक फ़ोल्डर — प्रत्येक फ़ाइल = एक अद्वितीय NFT। आप प्रत्येक को एक दुर्लभता भार निर्दिष्ट करते हैं। JSON/CSV कॉन्फ़िग प्रदान करें या मैन्युअल रूप से दर्ज करें।

```
my-nfts/
├── 001_samurai.png     (weight: 10 — legendary)
├── 002_ninja.png       (weight: 30 — uncommon)
├── 003_wizard.png      (weight: 5 — legendary)
├── 004_knight.png      (weight: 55 — common)
└── ...
```

कॉन्फ़िग (वैकल्पिक, JSON):
```json
[
  {"file": "001_samurai.png", "weight": 10, "name": "Samurai"},
  {"file": "002_ninja.png", "weight": 30, "name": "Ninja"}
]
```

### मोड C: एकल छवि

सभी NFT के लिए एक PNG। प्रत्येक टोकन समान दिखता है। सदस्यता पास, टिकट, उपयोगिता NFT के लिए अच्छा है।

```
collection-art.png    (संपूर्ण संग्रह के लिए एकल छवि)
```

### दुर्लभता भार (मोड A और B के लिए)

भार यह निर्धारित करते हैं कि प्रत्येक trait संस्करण कितनी बार दिखाई देता है। अधिक भार = अधिक सामान्य:

| श्रेणी | भार | आवृत्ति |
|----------|--------|-----------|
| Legendary | 1–4 | बहुत दुर्लभ |
| Rare | 5–19 | असामान्य |
| Uncommon | 20–49 | मध्यम |
| Common | 50–100 | बारंबार |

उदाहरण: यदि Headwear में Crown(5), Cap(30), Helmet(40), None(25) हैं, तो Crown लगभग 5% उत्पन्न NFT में दिखाई देगा।

## उपयोग

### 1. संग्रह निर्माण शुरू करें

एजेंट को बताएँ:
> "Deploy a generative NFT collection on Pharos"

एजेंट निर्भरताओं की जाँच करेगा, यदि आवश्यक हो तो `.env` बनाएगा, और इंटरैक्टिव कॉन्फ़िगरेशन शुरू करेगा।

### 2. कॉन्फ़िगरेशन प्रश्नों के उत्तर दें

एजेंट पूछेगा:
- **कौन सा नेटवर्क उपयोग करना है** — Pharos Atlantic Testnet (मुफ़्त, परीक्षण के लिए) या Pharos Mainnet (वास्तविक PROS टोकन)
- संग्रह का नाम और प्रतीक
- विवरण
- कुल आपूर्ति (अधिकतम NFT की संख्या)
- मिंट प्रकार (नीचे देखें)
- **आर्टवर्क मोड** — जेनरेटिव (traits), व्यक्तिगत छवियाँ, या एकल छवि
- आर्टवर्क विवरण: trait परतें, या PNG का फ़ोल्डर + भार, या एकल PNG का पथ

### 3. मिंट प्रकार

एजेंट प्रत्येक विकल्प को समझाएगा और आपको चुनने में मदद करेगा। छह प्रकार उपलब्ध हैं:

| प्रकार | विवरण | उपयोग का मामला |
|------|-------------|----------|
| **Public Free** | कोई भी मुफ़्त में मिंट कर सकता है | खुले सामुदायिक संग्रह |
| **Public Paid** | कोई भी एक निश्चित कीमत का भुगतान करता है | प्रीमियम संग्रह |
| **Owner-Only** | केवल कॉन्ट्रैक्ट मालिक मिंट कर सकता है | एयरड्रॉप, निजी वितरण |
| **Whitelist Free** | केवल व्हाइटलिस्टेड पते मुफ़्त में मिंट कर सकते हैं | विशेष सामुदायिक ड्रॉप |
| **Whitelist Paid** | केवल व्हाइटलिस्टेड पते भुगतान करके मिंट करते हैं | प्रीमियम सामुदायिक ड्रॉप |
| **WL Free + Public Paid** | व्हाइटलिस्टेड मुफ़्त में मिंट करते हैं, बाकी सब भुगतान करते हैं | सामुदायिक पुरस्कार + सार्वजनिक बिक्री |

व्हाइटलिस्ट प्रकारों के लिए, आपको पतों की एक सूची प्रदान करनी होगी (फ़ाइल या इनलाइन)। एजेंट स्वचालित रूप से एक Merkle tree उत्पन्न करता है और इसे कॉन्ट्रैक्ट में अपलोड करता है।

### 4. परिनियोजन के बाद

**NFT मिंट करें और वितरित करें:**
> "Mint 50 NFTs from my collection and send them to the addresses in airdrop_list.txt"

पता फ़ाइल प्रारूप — प्रति पंक्ति एक पता:
```
0xAAA...BBB...CCC...
# # से शुरू होने वाली पंक्तियाँ टिप्पणियाँ हैं
```

या इनलाइन:
> "Mint 3 NFTs and send to: 0xAAA..., 0xBBB..., 0xCCC..."

**होल्डर्स देखें:**
> "Show me all holders of my NFT collection"

**फ़ाइल में निर्यात करें:**
> "Export holder data to CSV"

**व्हाइटलिस्ट सेट करें:**
> "Set up a whitelist for my collection using these addresses: 0xAAA, 0xBBB"

**मिंट मापदंड अपडेट करें:**
> "Enable public minting at 0.05 PROS, max 5 per wallet"

## समस्या निवारण

| समस्या | समाधान |
|-------|----------|
| PNG आयाम बेमेल | सत्यापित करें कि सभी फ़ाइलें समान आकार की हैं, यदि आवश्यक हो तो पुनः निर्यात करें |
| IPFS अपलोड विफलता | `.env` में `PINATA_JWT` और Pinata खाता कोटा जाँचें |
| **Pinata: 500 फ़ाइल सीमा** | मुफ़्त योजना = 500 फ़ाइलें, 1 GB। मोड A: ~250 NFT (2N फ़ाइलें)। मोड B: 500-M NFTs तक। मोड C: ~500 NFTs तक |
| Forge नहीं मिला | स्थापित करें: `curl -L https://foundry.paradigm.xyz \| bash && foundryup` |
| Pillow नहीं मिला | स्थापित करें: `pip install Pillow` |
| **Stack too deep** त्रुटि | `foundry.toml` में `via_ir = true` जोड़ें — इस कॉन्ट्रैक्ट के लिए आवश्यक है |
| Forge संकलन त्रुटि | सुनिश्चित करें कि OpenZeppelin v5 स्थापित है: `forge install https://github.com/OpenZeppelin/openzeppelin-contracts@v5.0.2 --no-git` |
| Pharos पर लेनदेन विफल | हमेशा `forge create` और `cast send` के साथ `--legacy` फ़्लैग का उपयोग करें |
| अपर्याप्त गैस | Pharos पर वॉलेट शेष जाँचें |
| मिंट काम नहीं कर रहा | सत्यापित करें कि आप कॉन्ट्रैक्ट मालिक हैं, और सार्वजनिक संग्रह के लिए publicMintEnabled सत्य है |
| `.env` लोड नहीं हो रहा | प्रत्येक bash कमांड को `set -a && source .env && set +a` से शुरू करना होगा |
| एक्सप्लोरर में NFT छवि नहीं दिख रही | सुनिश्चित करें कि मेटाडेटा `ipfs://CID` का उपयोग करता है (गेटवे URLs नहीं)। फ़ोल्डर CID सत्यापित करें। |

## सुरक्षा

- **कभी भी** प्राइवेट की, JWT टोकन, या किसी भी रहस्य को चैट में पेस्ट न करें
- सभी रहस्य **केवल `.env` फ़ाइल में** संग्रहीत हैं — एजेंट इसे स्वचालित रूप से पढ़ता है
- `.env` स्वचालित रूप से `.gitignore` में जोड़ा जाता है
- `state.json` भी `.gitignore` में जोड़ा जाता है
- सुनिश्चित करें कि आप कॉन्ट्रैक्ट की मालिक कुंजी नियंत्रित करते हैं
- यदि आप गलती से कोई रहस्य चैट में पेस्ट कर देते हैं — तुरंत उस कुंजी को बदलें

## आउटपुट फ़ाइल संरचना

Skill चलने के बाद, आपके प्रोजेक्ट में निम्नलिखित होंगे:

```
project/
├── .env                         # आपके रहस्य (कभी कमिट न करें!)
├── .gitignore                   # .env और state.json बाहर रखे गए
└── nft-collection/
    ├── traits/                  # मूल trait PNG फ़ाइलें (मोड A)
    ├── composed/                # संयोजित अंतिम NFT छवियाँ (Pillow)
    ├── metadata/                # प्रत्येक टोकन के लिए JSON मेटाडेटा (ID द्वारा नामित)
    ├── src/                     # Solidity कॉन्ट्रैक्ट (Foundry)
    ├── landing/                 # मिंटिंग वेब पेज (वैकल्पिक, Phase 5)
    ├── state.json               # स्थानीय संग्रह डेटाबेस
    └── holders.json             # होल्डर डेटा (एनालिटिक्स के बाद)
```
